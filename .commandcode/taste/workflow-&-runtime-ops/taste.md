- When an image upload is reported as still failing "padahal ukuran di bawah 2MB", size is usually not the cause in this Flutter + Node/multer stack: Dart's `http.MultipartFile.fromBytes` omits Content-Type unless `contentType:` is passed, so the server receives `application/octet-stream` and its image-only mimetype validation (multer, JPG/PNG/WebP/GIF) rejects the part with 400 regardless of byte size — proven by live API tests posting the identical PNG as octet-stream (rejected) vs image/png (accepted). Durable fix: map the filename extension to the MIME type and set `contentType:` on every multipart image part (fallback `image/jpeg` for camera/gallery files), done once in the single shared send method so both add and edit flows are covered. - Flutter project rule for modal dialog content: a centered `AlertDialog` wraps its `content` in an `IntrinsicWidth`, and scroll views cannot return intrinsic dimensions — so putting a `ListView` (even `shrinkWrap: true`, i.e. `RenderShrinkWrappingViewport`) inside dialog content throws `RenderShrinkWrappingViewport does not support returning intrinsic dimensions` and the dialog never renders (symptom: a filter/modal "button" that seems to do nothing in debug/`flutter run`). Scrollable dialog content must instead be `ConstrainedBox(maxHeight: ...)` → `SingleChildScrollView` → `RadioGroup`/`Column(mainAxisSize: MainAxisSize.min)`, which keeps long option lists scrollable without triggering intrinsics. The old-vs-new structures were proven with a throwaway widget test (9 items: old = dialog invisible + exception, new = visible, `exception=null`), the scratch test deleted afterwards, and the whole `lib/` grepped to confirm no other dialog content uses `shrinkWrap` (the remaining hit sits in an Autocomplete `optionsViewBuilder` overlay, which is safe). Confidence: 0.7
